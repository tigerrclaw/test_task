# Агент допуска к огневым работам

Агент читает заявку свободным текстом и выдаёт `ДОПУСТИТЬ`, `ОТКАЗАТЬ` или `ЭСКАЛИРОВАТЬ`. Дата работ во всех заявках — 15.10.2026.

## Как устроен агент

Модель только извлекает факты: номер наряда, дата инструктажа, расстояние до склада угля или ГСМ, форма согласования, огнетушитель, наблюдающий, помещение или площадка, ветер, высота и допуск на высоту. В запросе стоит `response_format` со строгой JSON-схемой. Качественные слова («начало весны», «умеренный ветер») остаются пустыми: модель их не превращает в числа.

Решение считает обычный код по пунктам П1–П7. Приоритет: **ОТКАЗАТЬ > ЭСКАЛИРОВАТЬ > ДОПУСТИТЬ**. Границы в коде, не в промпте: инструктаж не раньше 15.04.2026; «ближе 10 м» — строго меньше 10; ветер запрещён строго выше 10 м/с и только на открытой площадке; высота требует человека строго выше 1,8 м. П6 сам по себе не даёт отказ. Так сделано, чтобы порог и приоритет не зависели от настроения модели.

Пустая заявка, текст длиннее 12 000 символов, битый JSON и недоступный провайдер дают эскалацию, не допуск и не падение процесса. Запасной провайдер необязателен; если задан, к нему переходят после пауз 10, 20 и 30 секунд с джиттером.

## Защита от инструкций в заявке

Заявка №8 содержит команду поставить «ДОПУСТИТЬ». Текст обёрнут в `<application>` и в промпте помечен как недоверенные данные. Модель не пишет решение: в схеме нет такого поля. Даже если в ответе появится «ДОПУСТИТЬ», код отбрасывает лишнее и заново считает П1–П7 по фактам. Без даты инструктажа итог — эскалация по П7, а не допуск по команде из текста.

## Запуск

Ключи только в `--env-file`: `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`.

```bash
docker build .
docker run -v <папка>:/data --env-file <файл> <образ>
docker run --entrypoint ./run_tests.sh <образ>
docker run -v <папка>:/data --env-file <файл> <образ> eval
```

`<папка>` — корень проекта. Контейнер читает `data/input.json`, пишет `data/output.json` и журнал `data/journal/request_ГГГГММДД_ЧЧММСС.json`. В корне появляются `results.json` и `eval_report.md`. Если `input.json` лежит сразу в смонтированной папке, читается он.

### Меню

Меню нужно, чтобы не открывать JSON и README в редакторе: посмотреть текущий регламент и пункты П1–П7, вспомнить команды запуска и проверить одну заявку текстом из терминала. Пороги в меню только показываются, менять их оттуда нельзя.

```bash
docker run -it -v <папка>:/data --env-file <файл> <образ> menu
```

Локально (Windows): `$env:PYTHONPATH = "src"`, затем `python -m hotwork menu`.

Пункты: `1` — регламент и П1–П7, `2` — справка по запуску, `3` — вставить текст одной заявки и отправить пустой строкой, `4` — выход. Журнал ручной проверки — `manual_request_ГГГГММДД_ЧЧММСС.json`.

### Регламент

По умолчанию пороги лежат в `src/hotwork/regulation.json`. На один прогон их меняют флагами после имени образа (или локально после `python -m hotwork`):

```bash
docker run -v <папка>:/data --env-file <файл> <образ> \
  --work-date 2026-10-15 --instruction-months 3 --hazard-distance 15 \
  --max-wind 12 --height 2 --max-text-chars 12000
```

Целый файл: `--regulation /config/regulation.json` или `REGULATION_PATH` в env-файле; файл должен быть виден в контейнере. В журнал пишется уже применённый набор. Новое правило на защите по-прежнему добавляется функцией в `src/hotwork/rules.py` и строкой в `RULES`.


## CI

На push и pull request GitHub Actions проверяет три уровня: `./run_tests.sh` (юнит-тесты), отдельно **mocked LLM** (`tests/fixtures/mock_llm_responses.json` + `tests/test_mock_llm.py`) и сборку Docker с тем же прогоном внутри образа. Живой LLM API в CI не вызывается — без ключа и без зависимости от внешнего сервиса. Workflow: `.github/workflows/tests.yml`.

## Качество

Eval: заявки 1–8 и 15 своих границ (`eval/cases.json`). На промпте `v4` и регламенте по умолчанию:

| Модель | Eval | Средняя задержка | Токены на заявку (вход / выход) |
|---|---|---|---|
| `gpt-6-astra` | **23 / 23** | ≈ 6 с | ≈ 1290 / 225 |
| `grok-4.7` | **23 / 23** | ≈ 19 с | ≈ 4810 / 1550 |

Astra и Grok на одних и тех же 11 заявках дали одинаковые решения. Astra быстрее и дешевле по токенам на этом эндпоинте; Grok тоже проходит весь eval, но дольше. Подробности — `eval_report.md`, `eval_report_astra.md`, `eval_report_grok.md`, `model_comparison.md`.

Стоимость в долларах не посчитана, пока не заданы `LLM_INPUT_USD_PER_1M` и `LLM_OUTPUT_USD_PER_1M`. Юнит-тесты без сети закрывают границы правил, разбор JSON и сбои.

## Ограничения

Ошибка почти всегда в фактах, а не в правилах: модель может перепутать «площадку у мастерской» с помещением, принять год в дате неверно или не отличить «согласование есть» от письменного. Слабые модели иногда не узнают сокращение «НД» — в промпте оно расшифровано, но парсер всё равно зависит от модели. «Около» у порога эскалируется с запасом 15 % или 0,3; далёкое «около 3 м» считается превышением. Годный, но слишком длинный наряд эскалируется целиком.

Заявки 9–11 при верных фактах: 12 м — допуск; «начало весны» и «умеренный ветер» — эскалация; 9 м и устное согласование — отказ по П3.

## 500 заявок за смену

500 заявок за смену — около одной в минуту за 8 часов. Узкое место здесь — внешний LLM API и его надёжность: сотни вызовов с ретраями, latency, rate limits, ошибки API и стоимость. Даже 1 % ошибочных решений — около пяти заявок за смену: для допуска к опасным работам это другой класс риска, чем для чат-бота. На объёме JSON-журналу понадобятся нормальное хранилище, а не папка с кучей json, уникальные id запросов, очереди, так как пперед сменой или аварийными работами может прийти одновременный поток из десятков заявок.

Первым делом необходимо организовать надёжный контур вокруг модели: очередь → извлечение фактов → проверка схемы → правила → решение и аудит. Таймаут, мусорный ответ или исчерпанные ретраи → **ЭСКАЛИРОВАТЬ**, никогда **ДОПУСТИТЬ**. Обработка асинхронная со статусами processing / completed / escalated / failed, чтобы простой модели не ломал процесс. После этого на реальной нагрузке смотреть p50/p95 latency, долю ошибок, стоимость и долю эскалаций — и только по этим метрикам решать, нужно ли горизонтальное масштабирование.
